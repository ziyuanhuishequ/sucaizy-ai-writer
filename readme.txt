输入公开链接、GitHub 项目地址、软件名称或素材名称，生成素材资源网风格的中文文章并保存为 WordPress 草稿。

== 安装 ==

1. 在 WordPress 后台进入“插件 > 安装插件 > 上传插件”。
2. 上传 sucaizy-ai-writer-x.y.z.zip 并启用。
3. 打开“素材 AI 写作 > 接口设置”，填写 API Key、API Base、模型和接口格式。
4. 点击“测试 API 连接”，测试成功后保存设置。
5. 打开“素材 AI 写作 > 写作 Skill”，按需要修改标题、语气、字数和文章结构并保存。
6. 回到“素材 AI 写作”，输入链接或名称，生成并检查文章，然后保存为草稿。
7. 管理员登录后打开 /newposts-2，在“保存草稿 / 提交发布”卡片下方点击“AI 写文章”，生成后可一键填入投稿编辑器。

== 源码与问题反馈 ==

* 源码地址：https://github.com/ziyuanhuishequ/sucaizy-ai-writer
* 遇到问题请附上插件版本、WordPress 版本和 PHP 版本，设置页底部的“运行环境自检”可以直接看到。

== 升级 ==

* 不要先删除旧版本再装新版。删除时 WordPress 会执行 uninstall.php，API Key、接口设置和自定义写作 Skill 会被一并清空。
* 正确做法：后台“插件 > 安装插件 > 上传插件”上传新 zip，弹窗选“替换当前版本”，插件会原地升级，设置和文章都保留。
* 也可以用 FTP/SFTP 把新包里的 sucaizy-ai-writer 文件夹内容覆盖到 wp-content/plugins/sucaizy-ai-writer/ 下，同样保留设置。
* 上传后如果提示“插件不存在”，先检查 wp-content/plugins/ 下是否出现了同名嵌套目录（如 sucaizy-ai-writer/sucaizy-ai-writer/）；有的话把内层文件整体上移一层，删掉多余的空目录即可。
* 如果更新后网站白屏或提示“此站点遇到了致命错误”：用宝塔面板文件管理把 wp-content/plugins/sucaizy-ai-writer 重命名为 sucaizy-ai-writer.disabled，网站会立刻恢复；重命名不会执行卸载脚本，API Key 和写作 Skill 都还在。
* 插件目录名必须是 sucaizy-ai-writer，主文件名必须是 sucaizy-ai-writer.php，两者不要改名。

== 功能 ==

* 支持公开网页、GitHub 仓库、软件名称和数字素材名称。
* 网页、GitHub API、最新 Release 和参考检索改为并发抓取，同一轮请求内完成，明显缩短等待时间。
* 输入框里出现 GitHub 地址时，「生成文章」旁边会多出「下载 GitHub 内容」：列出所有版本的安装包，可勾选、可指定保存目录、按系统自动分文件夹，下载完成直接给出站内链接。
* 资料默认缓存 180 分钟，同一链接再次生成会直接复用，生成速度最快；后台可一键清空缓存。
* GitHub 链接自动读取 Stars、许可证、主要语言和最新 Release。
* 默认生成 5 个备选标题（3-10 可调），每个标题 43-67 个汉字（多数 50-60 字），写成完整一句话；程序会过滤超长、空洞夸张、不含资源名称的标题，并自动在标点处收短。
* 模型只输出结构化 JSON（标题、简介、栏目条目），排版、三级标题、栏目标题由程序统一生成，输出更短、更快、更稳定。
* 简介自动控制在 100-180 字，超长会在标点处收短。
* 软件特点固定 5-6 条，每条“标签：说明”合计 35-45 字（约 40 字），超出自动收短，并在结果中提示字数。
* 软件类自动补一条独立的“支持系统”，无资料时按 Skill 写“支持系统：待核实”。
* 自动检索 B 站高播放视频和两路网页搜索（介绍类、体验类）里已有的同款介绍，把它们的标题和文案摘要一起交给模型，参考选题角度、读者痛点和真实说法，再用自己的话重写（可在设置里关闭）。
* 简介写成真人用过之后的推荐口吻，句子长短交替，不再像产品说明书。
* 软件特点与软件截图使用三级标题。
* 特点标签在 WordPress 编辑器中为真实粗体，不包含 Markdown 星号。
* 支持 OpenAI Responses API 和常见 OpenAI 兼容 Chat Completions 接口。
* 生成结果需人工检查后保存为草稿，不会自动发布。
* 生成后可点“换一批标题”只重做标题，正文保持不变，复用已缓存资料。
* 结果面板显示总耗时、抓取耗时、AI 耗时和特点字数达标情况。
* 生成结果附带“校验提示”，列出缺少资料支持的数字、平台和夸张表述，方便发布前核实。
* 在前端投稿页生成文章，并写入普通表单、TinyMCE 或 contenteditable 编辑器。
* 可使用短代码 [sucaizy_ai_writer] 在其他页面显示前端生成器。
* 生成、保存和前端写入功能仅限已登录管理员使用。
* API 地址、密钥、模型和接口格式必须实际测试通过后才能生成；配置变化后需要重新测试。
* 后台可以直接编辑写作 Skill，保存后下一篇文章立即生效，不需要更新插件或重新测试 API。
* 写作 Skill 可以控制标题数量与长度、文章语气、简介字数、栏目顺序、特点写法和各类资源模板。
* 结果面板显示本次 token 用量与估算费用（DeepSeek 官方单价，区分高峰和空闲时段）。
* 对 DeepSeek 接口默认关闭思考模式，写结构化 JSON 用不上思维链，可省一半以上费用。
* 自定义 Skill 保存在 WordPress 数据库中，正常升级插件时会保留；卸载插件时会随其他插件设置删除。

== 注意事项 ==

* API Key 保存在 WordPress 数据库中，请限制后台管理员账号并启用 HTTPS。
* DeepSeek 高峰时段为北京时间周一至周五 9:00-12:00 和 14:00-18:00（法定节假日除外），其余时段单价减半；估算费用按本机时间自动切换。
* 费用估算仅供参考：只统计插件自身发出的请求，按 DeepSeek 公开单价换算，实际账单以平台用量页为准。
* 插件会独立检索 B 站和网页参考；Responses API 的 web_search_preview 是可选的额外搜索能力，开启后会变慢，一般建议关闭。
* 第三方网站可能禁止抓取；这时可改用名称输入，并在“补充说明”中提供关键资料。
* 自动生成的价格、授权、版本和兼容性信息应在发布前人工核实。
* api.sudocode.chat 等 OpenAI 兼容服务通常选择“OpenAI 兼容 Chat Completions”，API Base 填写到 /v1。
* cURL error 28 表示 WordPress 所在服务器无法及时连接 API 主机，通常需要检查服务器 DNS、443 出站网络、防火墙或代理线路。
* 网页返回 cURL error 52 或其他抓取错误时，插件会记录警告并继续使用链接、补充说明和可用搜索资料生成，不再直接中断。
* 从 1.5.0 升级时，如果写作 Skill 仍是 1.5.0 的内置默认内容，插件会自动改用 1.6.0 的新默认规范；自己改过的 Skill 不会被覆盖。

= 1.6.6 =
* 修复 PHP 8 / 8.3 下“点了没反应”：PHP 8 会在运行时抛出新的 deprecation 和 warning，主机开启 display_errors 时这些文字会插在 AJAX 返回的 JSON 前面，前端解析失败。现在所有 AJAX 响应都会先丢弃意外输出（同时写进 error_log），JSON 不会再被污染。
* 修复中文乱码：抓取 GBK / GB2312 / BIG5 编码的中文站点时，页面内容会被 libxml 当成西欧编码重读，出现“½ØÍ¼¹¤¾ßÏÂÔØ”这种乱码并带进提示词。现在会先识别编码并转成 UTF-8，再改写页面里的 charset 声明后解析。
* 修复非法 UTF-8 导致正文丢失：preg_replace  在坏字节上返回 null，PHP 8.1+ 会抛 deprecation 并且整段资料变成空字符串。现在所有入口统一做 UTF-8 清洗，保证永远拿到合法字符串。
* 修复没有 mbstring 时中文被按字节截断造成的乱码：截断改为按 UTF-8 字符边界处理，不依赖 mbstring 也能正确工作。
* 修复排版错乱：千分位和时刻里的英文逗号、冒号（1,000 / 10:30）不再被换成全角，正文里不会出现“1，000”。
* 修复特点条目被硬截断后读成半句话（例如“…做产品说明和教程时特。”）：优先在标点处收短，实在没有标点才截断，并用省略号收尾。
* 修复“支持系统”“适用平台”这类平台清单被补上句号（“支持系统：Windows。”）的排版问题。
* 模型把链接、标题等字段返回成数组时不再触发 PHP 8 的 TypeError（PHP 7 里只是警告，PHP 8 会直接中断）。
* 设置页新增“运行环境自检”，直接列出 PHP 版本、json/openssl/mbstring/curl/dom 扩展状态和脚本超时，升级 PHP 后能一眼看出缺什么。
* 资料缓存版本升级到 v8，升级后第一次生成会重新抓取，避免继续使用带乱码的旧缓存。

* 修复：短代码所在页面之前没有在 wp_head 阶段排入样式，导致短代码页的生成器没有样式。现在正文含短代码的页面会自动加载样式和脚本。
* 修复：简介超过 180 字被收短后，结尾会出现“。。”或“！。”这种连续标点。现在收短后会一并去掉句末标点再补一个句号。
* 修复：模型把某个字段返回成数组时（例如简介返回成多段数组），正文里会出现字面量“Array”，同时产生 PHP 警告并可能让结果面板解析失败。现在会安全取第一段文字。
* 修复：标题校验里“资源名称不在结尾附近”的判断混用了字节位置和字符数，中文标题下几乎不生效；现已改为按字符比较。
* 修复：特点条目重新补上“标签：”后可能再次超出字数上限，现在会再收一次。
* 修复：去掉结尾悬挂连接词时用字节切片比较中文词，导致“以及”“和”这类词残留；现已改为按字符比较。
* 修复：标题去重键在遇到非法 UTF-8 时会变成空字符串，导致后续正常标题被误判为重复全部丢弃。
